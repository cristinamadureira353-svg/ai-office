## 0. 一页纸结论

现在办公室里**并排跑着两套系统**：一套是上一代模拟经营游戏（假客户、假员工、体力心情、资金声誉），一套是真 MiniMax Bot 团队（真任务、真模型、真消耗）。两套共用一套界面，用户看到的是矛盾的信息——比如右边「指令与待办」里的三条其实是**假客户订单**，不是 Bot 的任务。

本方案做四件事：

1. **修界面硬伤**（按钮遮挡、看不到回复、模型不显示）
2. **数据接真**（待办改读真任务、聊天接真 Bot、顶栏换真统计）
3. **砍玩法**（客户、接单、钱、体力心情、轮休、团建、每日结算）
4. **收尾**（旧存档不迁移、测试清理、全量验收）

保留：办公室场景、员工走动、闲聊、甩锅、关系八卦、会议（改成站会白板）。

## 2. 现状诊断（均为实测）

### 2.1 两套系统并存的证据

| 现象 | 代码事实 |
|---|---|
| 「指令与待办」显示的是假客户单 | `game_hud.gd:181` 过滤 `state.clients` 的 `等待/抢单中/服务中/待验收`，金额取 `reward` |
| 真任务在另一个小面板 | `game_hud.gd` `_draw_bot_board()`，数据来自 `/api/office/panel` |
| 员工「聊天」连的是假人 | `main_controller.gd` → `sse.send(who, text)`，走旧 Python 后端的 SSE |
| 「对 Chief 说…」连的是真 Chief | `backend_link.gd:167` → `/api/office/task` → `engine.sendUserMessage` |
| 发完看不到回复 | 只推两句本地生成的文字（`main_controller.gd:285-287`），真回复落在 `/bot` 面板 |
| 小人与模型无关 | `main_controller.gd:10` `DEFAULT_SLOTS=["m3","flash","longcat","kimi","step5"]`，模型只在详情页一行（`worker_panel.gd:145`） |

### 2.2 三个可见缺陷

**缺陷 A：按钮遮挡任务行**
`_draw_bot_board()` 中面板是 `Rect2(12, 74, 420, 118)`；三行文字纵向 110–170；「对 Chief 说…」按钮纵向 **158–184**，与第三行重叠 12px，且后绘制 ⇒ 盖住第三行。另有 `if i >= 3: break`，第 4 个任务直接消失且无提示。

**缺陷 B：发完看不到输出**
真 Bot 的回复、工具调用、失败原因全部只存在于 `/bot` 面板；办公室没有任何读取通道。

**缺陷 C：模型没对上**
卡片不显示模型；事件滚动条里还喊着 `LongCat / Flash / M3 / Kimi` 这些旧假人的名字，与真员工（前端/后端/审查）矛盾。

### 2.3 数据现状

- **token 数据已存在**：宿主本地库 `~/.minimax/v2/sqlite/runtime-state.sqlite` 的 `local_runtime_token_usage` 表，153,837 行，字段含 `session_id / model / input_tokens / output_tokens / reasoning_tokens / cache_read_tokens / cache_write_tokens / cost_usd`，覆盖 15 个模型。
  实测可归属：后端会话 20 行（输入 360,184 / 输出 68,911）、审查 97 行（369,202 / 205,538）、前端 98 行（944,010 / 211,543）；今日 `k3-256k` 12 次调用（314,607 / 7,946）。
- **插件侧没有 token**：`usage.jsonl` 只记 `durationMs / chars / tools / attempts`；`/api/usage` 只是按天/小时分桶。
- **旧存档里没有需要保留的东西**：`save.py` 的 `snapshot` 存的是 天数/钱/声誉/员工体力心情/客户列表/槽位/随机数种子；Bot 绑定存在 `office-map.json`（Node 侧），不在存档里。
- **测试规模**：Godot 17 个、Node 12 个、Python 6 个。

## 5. 关键技术方案

### 5.1 token 统计：读宿主台账

**为什么不用网关**
- 本机当前**没有网关在跑**（回环端口只有 MiniMax 客户端、Qoder、StepCode、飞书、微信）
- Bot 的模型请求由**宿主**发起，插件插不进调用链
- 要让流量过网关，必须改宿主全局 provider 地址 ⇒ 影响所有会话，且代理故障会打断全部对话

**采用的方案**
```
botId ──(消息记录里的 sessionId)──> 宿主台账 session_id
                                        │
                                        └─ 按 model 分组 → 输入/输出/缓存/成本
```

- 数据源：`~/.minimax/v2/sqlite/runtime-state.sqlite` → `local_runtime_token_usage`
- 只读打开（`mode=ro`），设置短超时
- 缓存 30–60 秒，避免每次刷新都查库

**降级策略（必须有）**
1. 库不存在 / 无权限 / 表结构变了 ⇒ 顶栏该格显示「—」，其余功能不受影响
2. Bot 换过会话（sessionId 变更）⇒ 按 bot 维度的历史 session 列表累加
3. `model` 为空的历史行 ⇒ 归到「未记录」分组，不参与"按模型"排名

**已知风险**：这是读宿主内部表，属跨层依赖。若宿主以后提供正式 API，应切过去；封装在单独模块里，切换只改一处。

### 5.2 员工聊天接真 Bot

- 发送：`POST /api/office/chat {bot_id, text}` → `engine.sendUserMessage('bot:'+bot_id, text)`
- 接收：订阅现成的 `/api/events`（SSE，`bot_bridge.mjs:131-135` 已有广播器），按 `chatId` 过滤
- 渲染：复用 `chat_panel` 已有的「同一气泡逐片追加」能力
- 降级：SSE 断开时退化为 2 秒轮询该 Bot 最后一条消息
- 注意：给真 Bot 发消息**会消耗一次模型调用**，界面上要写明（与「打回」一致）

### 5.3 站会白板

- 位置：会议室白板（现 `meeting_props.gd`）
- 内容三段，全部来自 `/api/office/panel`，**零模型调用**：
  1. 谁在做什么（`staff[].status` + 当前任务标题）
  2. 谁卡住了（`failed` / `error` / 排队超时）
  3. 还剩几单（`batches` 未完成计数）
- 可选：白板上一个「让 Chief 说两句」按钮 → 触发**一次**调用，让 Chief 用三句话总结并写进「最近事件」
- 默认不花调用，按了才花——按钮上标注

### 5.4 甩锅 / 关系的新燃料

| 触发事件 | 甩锅 | 关系变化 |
|---|---|---|
| 任务失败 / 被打回 | 触发；背锅者 = 最后一个动手的人 | 双人 −N |
| 审查判「不通过」 | 触发；锅落在被评一方 | 审查 ↔ 被评方 −N |
| 一次派活 | — | 派单方 +1、接单方 ±（按结果） |
| 等某人超过阈值 | 触发抱怨 | 双方 −1 |
| 同一件事被退回两次 | 触发（升级） | 大幅 −N |

**频率限制**：一轮任务最多触发一次甩锅，避免烧 token。

### 5.5 旧 Python 后端的去留

**结论：保留，做减法，不停服务。**

理由：走位、闲聊、关系、冲突、甩锅的实现都在 `ai-model-party/server/`（`game.py` 的寻路与 tick、`banter.py`、`relations.py`、`conflict.py`）。整块停掉员工就不动了。

做法：从 `game.py` 里摘掉客户/钱/体力/每日结算，保留 tick、寻路、说话、关系。

## 7. 风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 读宿主 sqlite 属跨层依赖 | 宿主升级后可能失效 | 封装单模块 + 降级为「—」，不影响其他功能 |
| 砍玩法动了 `game.py` | 员工可能不动/不说话 | 分批改，每批跑一次 Python 测试；先备份该文件 |
| 聊天接真 Bot 后成本上升 | 用户随手发一句就花钱 | 发送前提示「会消耗一次模型调用」；沿用 200 字上限 |
| 删客户端代码遗漏引用 | 编译报错/运行崩溃 | 全仓搜 `clients`/`ClientNode` 后再删；headless 全量测试兜底 |
| 站点按钮布局改动 | 其他面板错位 | 只改 `_draw_bot_board()` 内部常量，不动全局布局 |

**回滚点**：每批改动前对相关文件做 sha256 快照 + 复制到 `build/backup-<批次>-<时间>/`；仓库未纳入 git 的文件较多，**不能依赖 `git diff`**。
